# Surfare-Final

Surfare is an offline-first React and Vite digital safety application with a local Node detector API.

## Structure

- `frontend/` - React/Vite web application
- `backend/` - Local detector API, detection engine, datasets, optional services, and Cloudflare Worker
- `package.json` - npm workspace commands

## Run

```sh
npm install
npm run backend:dev
npm run dev
```

Open the frontend at `http://localhost:5173`. The Vite server proxies `/api/*` to `http://127.0.0.1:8790`.

## Install the Chrome extension

The extension runs in **desktop Chrome 116 or later**. You can install it for
testing now using Developer mode; it is not listed in the Chrome Web Store yet.

### Install from this repository

1. Download and extract this repository, or clone it with Git.
2. Install **Node.js 22.13 or later** with **npm 10 or later**.
3. Open a terminal in the repository root (the folder containing this README)
   and run:

   ```sh
   npm install
   npm run extension:build
   ```

4. Open `chrome://extensions` in desktop Chrome.
5. Turn on **Developer mode**, then choose **Load unpacked**.
6. Select the generated **`extension/dist`** folder. Choose the folder containing
   `manifest.json`, not the repository root or the `extension` source folder.
7. Open Chrome's Extensions menu and pin **Surfare — Check with Surfy**.

`extension/dist` is generated by the build and is not included in the GitHub
source download. You do not need to run the local website or backend to use the
extension's local checks or its configured production online services.

### Install a prepared extension ZIP

If someone gives you the built Surfare extension ZIP, extract it first. Follow
steps 4–7 above and select the extracted folder containing `manifest.json`.
Node.js and the build commands are not needed for this method. Keep the
extracted folder in place after installation.

### Use and update it

- Highlight text on a webpage, right-click it, and choose **Check selected text
  with Surfare**. You can also right-click a link or image for its Surfare option.
- Read the result in the side panel, then select **Ask Surfy** for questions.
- Right-click checks run on your device first. Enable **Use online help** and
  press **Check with online help** when you want an online check.
- After getting updated source code, run `npm run extension:build` again. Then
  click **Reload** on Surfare in `chrome://extensions`, close the side panel and
  reopen it. For a prepared ZIP, replace the extracted files with the new build
  before reloading.

The extension connects to `https://surfare.vercel.app` for online features.
API credentials stay on the server. See [the extension guide](extension/README.md)
for permissions, image limitations, local development and verification commands.

## Share to Surfare on Android

Install the deployed HTTPS app from Chrome on Android. In an app that offers
sharing, press and hold a message, link or image, choose **Share**, then
**Surfare**. Messages and links fill the matching detector; an image opens the
image-check options. The user still chooses **Check** before detector analysis
or an AI request. Messages containing a link stay intact in the message detector.

The manifest uses one multipart `POST /share-target/` share target. The generated
service worker imports `share-target.js` to receive the share on the device,
including offline. A random receipt ID opens the app; shared text and image
bytes never appear in the URL. IndexedDB holds at most three pending shares,
which are deleted when received by the page. Unopened receipts expire after
10 minutes and are deleted when opened or pruned on a later share. The app does
not keep a submission history. Images retain their original bytes and metadata.
Only one JPG, PNG or WebP image (up to 8 MiB), or 12,000 text characters, is
accepted per share. Unsupported and oversized items show a simple error.

This requires a supported installed PWA, not an ordinary browser tab. Existing
Android installations may need updating or reinstalling after deployment before
Surfare appears in the share sheet. The source app must offer **Share** for the
selected content; Surfare cannot add a long-press menu inside another app.
Safari on iPhone does not support Web Share Target; paste and image upload
remain available there. An iOS app with a Share Extension would be a separate
integration.

Use a production preview to test the receiver: `npm run build`, then
`npm run preview --workspace frontend -- --host 127.0.0.1 --port 4173` and
`node frontend/scripts/smoke-share-target.mjs`. This tests the actual service
worker, receipt storage, multipart input and offline flow in Chrome; verify the
OS share sheet separately on a physical Android phone after deployment.

## Optional AI help

Enable **AI help** in the checker to share the submitted text, check details,
and Surfy conversation with the configured AI services. Local findings appear
first while the additional assessment runs. Completed, pending, and unavailable
AI checks are shown separately. For links, the AI review is advisory only: it
can flag impersonation, gambling, credential/payment and scam cues from the
submitted text, but it never calls a link legitimate, verified, or safe. Safe
Browsing and the local reviewed lists remain authoritative. New chat questions
include recent conversation and the actual check context; chat answers never
change a verdict. Without this choice, or without internet, Surfy uses local
explanations.

When `AGENT_ROUTER_API_KEY` and `AGENT_ROUTER_MODEL` are set on the server,
Agent Router is tried first for text and Surfy chat. Copy the model ID exactly
from the Agent Router console or pricing page; an unavailable model returns an
error instead of silently routing to another one. The Agent Router names
`AGENTROUTER_API_KEY`, `AGENTROUTER_BASE_URL`, and `AGENTROUTER_MODEL` are also
accepted. Set `AGENT_ROUTER_BASE_URL` if your gateway is not
`https://agentrouter.org/v1`. It is followed by the reviewed free OpenRouter
model and the configured Gemini backup. Existing `OPENROUTER_API_KEY`,
`OPENROUTER_MODEL`, `GEMINI_API_KEY`, and `GEMINI_IMAGE_MODEL` settings still
apply. `AGENT_ROUTER_IMAGE_MODEL` enables an Agent Router vision model for image
review; without it, image review stays on the existing providers. Keys never
enter the frontend. `/api/surfy` serves chat; `/api/detect` runs the extra
assessment only when `ai: true` and `consent: true` are supplied. Provider errors
preserve local findings; AI findings require exact quotes from the submitted
text. Agent Router may be a paid service, so review your gateway billing and
data policy before enabling it.

The OpenRouter text/chat fallback is pinned to
`baidu/ernie-5.5-flash-preview:free`; image review is pinned to
`nvidia/nemotron-3.5-super-vl:free`. Only these reviewed OpenRouter models are
accepted. The old `openrouter/free` setting migrates to the relevant pinned
model. No random model or unreviewed OpenRouter fallback is used. Availability
and quality can change, so maintain this allowlist against local regression checks.

The local Gemini backup is configured with
`GEMINI_IMAGE_MODEL=gemini-3.5-flash-lite`. The same configured Gemini model is
used as backup for text detection and chat. Temporary server errors get one retry within
the existing request timeout; invalid keys and quota errors are not retried.

AI image checks inspect metadata in the original file on the device first. The
metadata result stays visible while the optional online check runs. When online
image sharing is selected, a resized JPEG is sent through `/api/image-detect`
to Sightengine's `genai` model. Set both `SIGHTENGINE_API_USER` and
`SIGHTENGINE_API_SECRET` in `backend/.dev.vars` locally and in Vercel's server
environment when deployed. Never prefix these credentials with `VITE_`.
Restart the local backend after changing them; redeploy after Vercel changes.

The result shows the provider score on a 0–1 scale. The application uses a low
signal band up to 0.2, an uncertain band between 0.2 and 0.8, and a high signal
band from 0.8. These are conservative display bands, not measured accuracy or
proof of authenticity. Metadata and the online score remain separate findings.
Offline, missing credentials, quota limits and provider failures preserve local
metadata findings. Retrying is explicit; no automatic retries or other image
providers are used by this flow. Sightengine account usage applies: `genai`
currently consumes five operations per image. The result and Surfy include the
provider score and limitations without inventing visual observations.

Surfy chat and text detection follow the configured server provider order.
Restart the local backend after changing `backend/.dev.vars`; redeploy Vercel
after changing its runtime environment. Provider failures and exhausted quotas
preserve Surfy's local explanations.

## Scam-awareness practice

Use **Play & learn** in the desktop header, or scroll to **Build your scam
radar**. Surfy's Scam Challenge contains six fictional Philippine scenarios,
each with two decisions, explanations, retry opportunities, and a completion
score. It follows the selected English, Filipino, or Taglish language. Best
completed scores are saved on the device and can be reset from the practice
section. The game makes no API calls and works offline after the app is cached.
Its authored scenarios are separate from detector training and evaluation data.

## Offline resources

On the first online visit, the installed app caches its page and then saves the
files needed for local image text checks in English and Filipino (about 19.3 MB)
in the background. **Download resources** below the checker still shows
progress, cancellation, and retry, and resumes from completed files. Completed
downloads stay on the device until browser storage is cleared. Surfare can be
installed from the browser menu or the **Install Surfare** button where the
browser offers it. After the first online visit, message, link, image, and QR
detection run locally offline; online reputation lookups, AI help, and feedback
are unavailable until you reconnect, and results say so.

The welcome tour includes the download option and the scam-awareness game.

## Validation commands

```sh
npm run backend:test
npm test
npm run build
```

With the local app running, `node frontend/scripts/audit-detectors.mjs` exercises
Text, Links, image text, QR content, and image-origin AI using authored fixtures.
It saves `artifacts/detector-audit.json`. Successful requests confirm integration;
they do not measure real-world accuracy. The existing dataset reports measure
individual offline model components, not the full application or live AI.
