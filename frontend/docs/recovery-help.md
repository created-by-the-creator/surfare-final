# Surfy Lifeguard

The website opens Surfy Lifeguard beside Play & learn and from check results. The navy popup shares the main page's palette, type, pale-blue chat bubbles and red actions. Ask Surfy starts closed and opens into its own view using the actual `AskSurfy.jsx` component. Returning to the checklist preserves both the conversation and selections. Official support cards are in a disclosure after the checklist; immediate emergency help remains visible. The extension retains its compact entry.

`RecoveryHelp.jsx` owns the temporary checklist; `RecoveryChat.jsx` owns the conversation. Closing the popup clears both. Neither writes these details to browser storage. Downloading the checklist is an explicit local action.

The guide suggests possible next steps without promising a fix or refund. Free-text provider and country fields support any service. Non-Philippine selections hide Philippine contacts. Offline chat uses translated local guidance.

## Optional AI help

The AI double-check starts off each time the guide opens. Users acknowledge the main privacy notice and separately enable it. Enabling sends nothing. Asking a question sends the question, service name, country, situation IDs, requested language and up to six recent chat messages through `/api/recovery-guide` to **OpenRouter first, then the configured Gemini backup**. There are no search tools or other providers.

Surfy uses AI knowledge to explain possible options. It cannot browse or verify current contacts, service hours, policies or menus. The instruction requires concise replies (25–55 words, one takeaway and at most two bullets), appropriate uncertainty and directing users to their usual app for current official support. Replies over 90 words or 900 characters, generated URLs and phone numbers are rejected. Official contact cards are maintained separately from AI output.

The server requires explicit consent, validates bounded context, rejects unrelated website origins and redacts common numerical identifiers and email addresses. Redaction is best effort; users should omit passwords, codes and account details. Surfare does not persist these requests. OpenRouter, its selected model provider and Google Gemini have their own data policies. Provider failures, timeouts and loss of connectivity show labeled local guidance. Ask Surfy chat now uses OpenRouter first with Gemini backup; the online image detector still uses Sightengine only.

Configuration uses `OPENROUTER_API_KEY` and `GEMINI_API_KEY`, with optional allowlisted `OPENROUTER_MODEL` and `GEMINI_IMAGE_MODEL`. No search-service configuration is required.
